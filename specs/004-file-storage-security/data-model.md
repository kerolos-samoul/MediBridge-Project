# Data Model: File Storage, Verification & Security Plumbing (Phase 4)

## Persistence Direction

Phase 4 stores file metadata, review history, scan status, access-grant audit records, and file audit events in SQL Server through Entity Framework Core in `MediBridge.Repository`. `MediBridge.Core` defines pure domain entities, enums, and repository contracts only. Cloudinary asset operations are service-layer behavior through `IFileStorageProvider`; Cloudinary SDK types and credentials do not appear in Core, Repository, controllers, SQL records, or logs.

Phase 4 extends the existing Phase 3 `StoredFile` entity rather than replacing it. Existing Phase 3 stored-file rows remain valid after migration.

## Entities

### StoredFile

Metadata record for verification documents, campaign media, voice notes, and clinical research attachments.

**Existing fields retained**:

- `Id`: unique file metadata identifier
- `OwnerType`: `Doctor`, `Company`, `Admin`, or `Campaign`
- `OwnerId`: owning profile/user/campaign identifier
- `Purpose`: `VerificationDocument`, `CampaignMedia`, `VoiceNote`, or `ClinicalResearchAttachment`
- `OriginalFileName`: sanitized original file name for display only
- `ContentType`: accepted content type
- `SizeBytes`: uploaded file size
- `StorageKey`: non-secret provider public ID/key
- `Visibility`: defaults to `Private`
- `ReviewStatus`: current review summary
- `CreatedAtUtc`: upload time
- `ReviewedAtUtc`: nullable latest review time
- `ReviewedByAdminId`: nullable latest reviewing admin
- `ReviewReason`: nullable latest review reason

**New or tightened fields**:

- `RelatedCampaignId`: nullable campaign reference for campaign media, voice notes, and clinical research attachments
- `StorageProvider`: provider name, expected `Cloudinary` for Phase 4
- `StorageResourceType`: `Image`, `Video`, or `Raw`
- `StorageDeliveryType`: `Private` or `Authenticated`
- `UploadStatus`: `PendingUpload`, `Stored`, `UploadFailed`, `Deleted`, or `Replaced`
- `SafetyScanStatus`: `NotAvailable`, `Pending`, `Passed`, `Failed`, or `Deferred`
- `SafetyScanCheckedAtUtc`: nullable scan status timestamp
- `DeletedAtUtc`: nullable deletion timestamp
- `ReplacedByFileId`: nullable replacement file reference
- `ConcurrencyStamp`: optimistic concurrency token for review/replacement updates

**Relationships**:

- A Doctor or Company owner may have many verification files.
- A Campaign may have many campaign media, voice note, and clinical research files.
- One `StoredFile` has many `FileReview` records.
- One `StoredFile` may have many `FileAccessGrantAudit` records.
- One `StoredFile` may replace or be replaced by another `StoredFile`.

**Validation Rules**:

- Verification and research documents are limited to 10 MB.
- Images are limited to 10 MB.
- Voice notes/audio files are limited to 25 MB.
- Campaign video files are limited to 100 MB.
- Documents must use `application/pdf` with `.pdf` or `application/vnd.openxmlformats-officedocument.wordprocessingml.document` with `.docx`.
- Images must use `image/jpeg` with `.jpg` or `.jpeg`, or `image/png` with `.png`.
- Audio must use `audio/mpeg` with `.mp3`.
- Video must use `video/mp4` with `.mp4`.
- The file extension and content type must both match the requested file purpose.
- Empty files are rejected.
- User-provided filenames are display metadata only and must not determine `StorageKey`.
- `StorageKey` must be generated by the server and unique.
- `StorageProvider`, `StorageKey`, `StorageResourceType`, and `StorageDeliveryType` must not contain secrets.
- Private/review-required files default to private visibility.
- Deleted, replaced, rejected, quarantined, or missing files are unavailable as approved evidence/assets.
- If the Doctor or Company owner is soft-deleted, rejected, suspended from normal access, or otherwise inactive, normal file access and replacement are denied; Admin audit access may still read metadata and review history.
- Replacement uploads create a new `StoredFile`, link the original through `ReplacedByFileId`, mark the original `UploadStatus` as `Replaced`, and set the new file to `Pending` review.
- Deletion marks `UploadStatus` as `Deleted`, sets `DeletedAtUtc`, attempts provider asset deletion through the storage abstraction, and preserves metadata/review history for audit.
- `SafetyScanStatus` may be recorded, but Phase 4 does not require a passing scan before approval.

### FileReview

Append-only admin decision record for a stored file.

**Fields**:

- `Id`: unique review identifier
- `StoredFileId`: reviewed file
- `AdminUserId`: reviewing admin
- `Decision`: `Approved`, `Rejected`, `Quarantined`, `ReplacementRequested`, or `Correction`
- `Reason`: required for rejection, quarantine, replacement request, and correction
- `Notes`: optional admin note
- `CreatedAtUtc`: decision timestamp
- `CorrectsReviewId`: nullable link to a corrected or superseded review

**Relationships**:

- Many reviews belong to one `StoredFile`.
- `AdminUserId` references an Admin identity user.
- A correction may reference one earlier `FileReview`.

**Validation Rules**:

- Append-only; previous review rows are not modified or deleted to express corrections.
- Reviewer must be an Admin user.
- Correction records must reference the review they correct.
- Rejection, quarantine, replacement request, and correction require a reason.

### FileAccessGrantAudit

Non-secret audit record that a private file access grant was issued or denied.

**Fields**:

- `Id`: unique audit identifier
- `StoredFileId`: target file
- `RequestedByUserId`: user requesting access
- `RequesterRole`: Doctor, Company, or Admin
- `Outcome`: `Issued`, `Denied`, or `Expired`
- `Reason`: non-secret outcome reason
- `ExpiresAtUtc`: grant expiry when issued
- `CreatedAtUtc`: request timestamp

**Relationships**:

- Many access-grant audit records belong to one `StoredFile`.
- Requesting user references an identity user.

**Validation Rules**:

- Do not persist signed URLs, private tokens, provider signatures, or credentials.
- Issued grants expire exactly 10 minutes after creation.
- Denied grants must not include private storage references.

### FileAuditEvent

File workflow audit represented by existing `AuditEvent` infrastructure.

**Target type**:

- Existing `AuditTargetType.StoredFile`

**Event types to represent in metadata**:

- Upload started
- Upload stored
- Upload failed
- Private access issued
- Private access denied
- Review decision recorded
- Replacement started
- Replacement uploaded
- File deleted
- Storage configuration validation failed

**Validation Rules**:

- Metadata must not include raw file contents, provider credentials, private access tokens, signed URLs, request bodies, or provider error payloads.
- Actor may be a user, admin, system, or anonymous source for denied unauthenticated attempts.

### FileStorageOptions

Service/API options for upload validation and provider behavior.

**Fields**:

- `UploadsEnabled`: enables or disables file upload features
- `DocumentMaxBytes`: 10 MB
- `ImageMaxBytes`: 10 MB
- `AudioMaxBytes`: 25 MB
- `VideoMaxBytes`: 100 MB
- `AccessGrantLifetimeMinutes`: 10
- `AllowedDocumentContentTypes`: exactly `application/pdf` and `application/vnd.openxmlformats-officedocument.wordprocessingml.document`
- `AllowedImageContentTypes`: exactly `image/jpeg` and `image/png`
- `AllowedAudioContentTypes`: exactly `audio/mpeg`
- `AllowedVideoContentTypes`: exactly `video/mp4`
- `AllowedExtensions`: exactly `.pdf`, `.docx`, `.jpg`, `.jpeg`, `.png`, `.mp3`, and `.mp4`

**Validation Rules**:

- Values must match clarified Phase 4 limits unless the spec is amended.
- Options must not contain provider secrets.

### CloudinaryStorageOptions

Provider options for service-layer configuration validation.

**Fields**:

- `CloudName`: non-secret cloud name or derived from secret URL
- `UseSecureUrls`: must be true
- `FolderPrefix`: non-secret provider folder prefix

**Secret input**:

- `CLOUDINARY_URL`: secret operator-provided credential URL

**Validation Rules**:

- `CLOUDINARY_URL` must be present when uploads are enabled and Cloudinary provider is selected.
- `CLOUDINARY_URL` must not be bound from appsettings or persisted.
- API key, API secret, credential URL, signatures, and access tokens must never be logged or returned.

## State Transitions

### StoredFile UploadStatus

```text
PendingUpload -> Stored
PendingUpload -> UploadFailed
Stored -> Deleted
Stored -> Replaced
UploadFailed -> PendingUpload (retry)
```

Replacement uses a new `StoredFile` row. The original row transitions to `Replaced` and points to the replacement through `ReplacedByFileId`; the replacement starts as `PendingUpload`, then `Stored`, and has `ReviewStatus = Pending`.

### StoredFile ReviewStatus

```text
Pending -> Approved
Pending -> Rejected
Pending -> Quarantined
Rejected -> Pending (replacement file only)
Approved -> Quarantined
Approved -> Rejected (new correction/superseding review)
```

### SafetyScanStatus

```text
NotAvailable -> Deferred
NotAvailable -> Pending
Pending -> Passed
Pending -> Failed
```

Phase 4 does not require `Passed` before review approval or campaign readiness.

## Repository Contracts

- `IStoredFileRepository`: create upload record, complete provider storage, mark upload failure, fetch by id, list by owner, list by review status, update current review summary, mark deleted, link replacement files, mark original as replaced, check owner active state for normal access, and check campaign readiness availability.
- `IFileReviewRepository`: append review decision, list review history, fetch review for correction.
- `IFileAccessGrantAuditRepository`: append grant issue/deny/expiry audit records.
- `IDomainUnitOfWork`: expose file repositories and commit metadata/review/audit changes atomically.

## Migration Requirements

- Preserve existing `StoredFiles` table and Phase 3 columns.
- Add new nullable columns where needed for backward compatibility.
- Add `FileReviews` and `FileAccessGrantAudits` tables.
- Add indexes for `(OwnerType, OwnerId, Purpose, CreatedAtUtc)`, `(RelatedCampaignId, Purpose)`, `(ReviewStatus, CreatedAtUtc)`, `(UploadStatus, CreatedAtUtc)`, `(ReplacedByFileId)`, and `(StoredFileId, CreatedAtUtc)` on review/audit tables.
- Add optimistic concurrency protection for `StoredFile` review/replacement updates.
